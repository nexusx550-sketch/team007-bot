# Team007: обработчик для Bothost

Сайт и база остаются на 141.8.198.89, домен team007.ru. На Bothost запускается только Telegram-обработчик. DNS не менять. Архив не содержит токена или данных команды. Внешних npm-зависимостей нет; нужен Node.js 22+ (в Dockerfile указан Node.js 24).

## Настройка

1. В Bothost выберите Базовый тариф или выше. По документации загрузка архивов пока доступна на одной тестовой ноде: проверьте доступность опции до оплаты длительного периода.
2. Профиль → Интерфейс → Загрузка бота из архива → сохранить.
3. На старом сервере остановите старый обработчик, оставив сайт работать:

```sh
cd /opt/team007
docker compose --profile bot stop bot
```

На новом VDS обработчик пока не запускали. Не запускайте его параллельно.

4. Возьмите существующий TEAMBOARD_BRIDGE_KEY на старом сервере. Следующая команда выводит секрет только в ваш терминал; не присылайте вывод в переписку:

```sh
sed -n 's/^TEAMBOARD_BRIDGE_KEY=//p' /etc/team007/bot.env
```

5. Bothost → Мои боты → Загрузить из архива. Выберите этот ZIP, название Team007, токен @myteam007_bot от BotFather, язык Node.js, главный файл index.js. Если доступна опция «Использовать собственный Dockerfile», включите её. Запуск: node index.js (или npm start).
6. Добавьте переменные окружения:

| Имя | Значение |
| --- | --- |
| TEAMBOARD_URL | https://team007.ru |
| TEAMBOARD_BRIDGE_KEY | Значение с СТАРОГО сервера |
| BOT_STATE_FILE | /app/data/state.json |

Токен из поля мастера Bothost передаёт как BOT_TOKEN/TELEGRAM_BOT_TOKEN; код поддерживает оба имени. Если токен не передаётся, добавьте TELEGRAM_BOT_TOKEN вручную в переменные окружения. Не вписывайте секреты в код.

Если мастер сразу запускает контейнер без дополнительных переменных, добавьте их после создания в настройках и перезапустите. До заполнения настроек процесс остановится с сообщением Set TELEGRAM_BOT_TOKEN, TEAMBOARD_URL, TEAMBOARD_BRIDGE_KEY.

7. Запустите ровно один экземпляр. Это long polling: домен и webhook для бота не нужны. /app/data должен сохраняться между перезапусками. Сайт хранит задачи и привязки, а state.json хранит позицию обработки Telegram-событий. Не заменяйте и не удаляйте state.json при обновлениях. Если старый обработчик уже работал, перед первым запуском перенесите его /var/lib/team007-bot/state.json в data/state.json через файловый менеджер Bothost (только после остановки старого процесса). При прежнем сбое на getMe он ещё не обрабатывал сообщения, перенос файла не требуется.

## Проверка

Ожидаемый лог: Teamboard bot connected.
На сайте в разделе Telegram должен обновиться статус обработчика. Откройте персональное приглашение, нажмите Start, затем «Мои задачи». Проверьте вход по одноразовому коду в приватном окне браузера.

HTTP 401 от сайта обычно указывает на неверный ключ обработчика; HTTP 409 от Telegram возможен при втором работающем обработчике. При Connection error проверьте доступ с Bothost к api.telegram.org и team007.ru. Новый ключ на сайте делает старый ключ недействительным: обновите переменную и перезапустите бота.

При первичном сетевом сбое обработчик повторяет подключение через 5 секунд. Логи не выводят токены. Не удаляйте старый сайт или новый VDS до подтверждения работы бота; решение об удалении VDS принимается отдельно.

## Проверено

Синтаксис Node.js и запуск с имитацией Telegram и API доски проверены локально. Реальное подключение из Bothost ещё не проверено: его результат будет виден после размещения.
